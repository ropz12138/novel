## 修改要求

1. **精确修改**：只修改用户要求改动的部分，保持其他内容不变
2. **风格一致**：修改后的文风、人称、视角与原文保持一致
3. **上下文衔接**：修改部分的前后文要自然过渡，不能出现断裂
4. **字数弹性**：如果用户要求"详细/扩展"，适当增加篇幅；如果要求"精简"，适当缩减
5. **锚定片段**：search 字段必须是原文中实际存在的连续文本片段（至少20个字符），用于精确定位修改位置

## 输出格式

输出一个合法的 JSON 对象，包含 edits 数组。每个 edit 是一个局部编辑操作：

```json
{{
  "edits": [
    {{
      "type": "replace",
      "search": "原文中要被替换的连续片段（至少20字）",
      "content": "替换后的新内容"
    }},
    {{
      "type": "insert",
      "after": "原文中插入点之前的连续片段（至少20字）",
      "content": "要插入的新内容"
    }},
    {{
      "type": "delete",
      "search": "原文中要删除的连续片段（至少20字）"
    }}
  ],
  "summary": "简要说明做了哪些修改"
}}
```

### 操作类型说明

- **replace**：将 search 匹配到的原文片段替换为 content。用于修改已有内容。
- **insert**：在 after 匹配到的原文片段之后插入 content。用于添加新内容。
- **delete**：删除 search 匹配到的原文片段。用于移除内容。

### 重要规则

1. search/after 字段必须从原文中逐字复制，不要凭记忆改写，确保能精确匹配
2. 如果需要修改多处，在 edits 数组中按顺序列出多条操作
3. 每条操作的 search/after 片段至少20个字符，越长越精确
4. 只输出 JSON 对象，不要输出 JSON 以外的任何文字
5. 如果修改范围超过正文的50%，改为输出完整修改后正文（纯文本，非 JSON）
