## 构思要求

请从以下维度进行构思：

1. **本章定位**：本章在整体故事中的位置和作用（推进主线/转折/铺垫/高潮等）
2. **关键场景**：本章需要包含的场景列表，每个场景的核心事件
3. **出场角色**：本章需要出场的角色及其作用
4. **情感曲线**：本章的情感走向（如：紧张→绝望→希望）
5. **冲突与悬念**：本章的核心冲突是什么，结尾留下什么悬念
6. **一致性注意点**：基于前文回顾，列出需要特别注意的一致性问题
7. **需求回溯**：在完成构思后，回溯"用户指导意见"中的每一条要求，逐项检查是否已在构思中体现。对每个用户明确提出的点，在笔记中标注如何落实。如有遗漏的用户要求，自行补充到构思中或在笔记末尾列出"待确认"项。

如果用户提供了指导意见，请结合指导意见进行调整。

## 自我审查

构思完成后，请对照大纲和前文进行自我审查：
- 构思的场景是否与大纲纲要一致？有没有遗漏或越界？
- 角色的行为是否符合其性格和当前状态？
- 情节推进是否与前文自然衔接？有无逻辑矛盾？
- 如果发现问题，请在构思笔记中自行修正。

## 输出格式

先输出构思笔记正文（Markdown 格式），然后换行，输出一个 JSON 代码块，格式如下：

```json
{{
  "title": "第X章 章节标题",
  "outline_changes_needed": false,
  "outline_change_reason": "",
  "outline_change_operations": [],
  "needed_queries": ["伏笔F1的状态", "角色X上次出场时的位置"]
}}
```

标题要求：简洁有力，2-6个字，能概括本章核心内容或制造悬念，不要与已有章节标题重复。

`needed_queries` 列表：列出你构思过程中需要确认但前文回顾中未明确的信息。如果前文回顾已经足够，留空数组 `[]`。

如果构思过程中发现需要修改大纲才能继续（例如需要新增角色、调整章节范围等），将 `outline_changes_needed` 设为 `true`，并在 `outline_change_reason` 中说明原因，在 `outline_change_operations` 中列出具体的操作（格式同大纲编辑工具调用格式）。

如果不需要修改大纲，`outline_changes_needed` 保持 `false`，后两个字段留空。
