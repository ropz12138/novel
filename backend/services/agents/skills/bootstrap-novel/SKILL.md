# 初始化小说

本技能由 Supervisor 亲自执行。参考规则通过 `read_skill_reference` 按阶段完整加载，工具仅负责读取与保存。
参考文件中的结构化输出格式用于组织工作记录；设定使用节点工具保存，章节正文通过 `update_node` 保存，用户回复使用 `respond_to_user`。

## 创作参考前置

新内容设计与创作的必经环节是参考研究。Supervisor 先确定范围、目标体验及作者约束，工具集中有 `run_reference_agent` 时，本轮实际调用它。取回章节原文后完成本作化，再形成具体方案，并由你直接完成相应正文或设计。作者已有完整方案时，检索围绕其已确认内容取回相关章节原文。本轮未取回章节原文时，按当前作品已有事实、作者已确认的事件与设定完成本轮方案与正文。同一轮同一范围沿用本轮已取得的完整结果，扩大范围或改变核心方向时重新研究。取回原文时，将真实作品与章节来源、选择理由和适配方式写入当前任务记录及需要持久保存的完整设计。

## 完成标准

真实节点覆盖作品定位、核心角色、世界规则与社会生态和故事规划笔记；存在持续生效的创作要求时，同主题 `note` 已保存。章节顺序和内容已回读。

## 执行流程

1. 用 `get_canvas_index` 找出既有节点，`read_node_content` 读取全部笔记及相关作品资料，整理用户完整要求。当用户仅提供小想法、局部世界观或单一场景片段时，先锚定该片段的核心画面感与趣味点，向外反推所需的人物特质、世界规则与近期矛盾。
2. 用 `read_skill_reference` 加载本技能的 `premise_architect.txt`，按“近景具体可感、远景锚定悬念与核心矛盾”完成渐进式架构构思。持续生效的创作要求保存到同主题笔记；本轮一次性修改留在任务清单。笔记用简明条目表达当前有效决定、适用范围和必要例外，保留作者指定措辞与全部有效条件，同义要求合并表达。
3. 用 `create_node` 建立真实节点，记录 UUID；沿用已有节点时，局部调整 `content` 使用 `update_node(mode="replace", replacements=[...])`，整体重构才使用 `mode="overwrite"`。章节直接归属作品，使用 sort_order 确定章节顺序；长期故事规划保存到 note，逐章设计保存到章节笔记。
4. 由你把构思写入节点 `content`，以紧凑事实句呈现该节点负责的目标、关键因果与结果，将角色发展线写入 `storylines`，角色定位写入 `scope`。设计推演和修改经过保留在当前任务记录中，节点内容便于作者直接判断故事。
5. 回读节点和笔记，检查章节顺序、因果、用户约束与内容一致性，修订更新原 UUID。
