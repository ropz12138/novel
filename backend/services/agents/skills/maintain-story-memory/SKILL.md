# 维护故事记忆

本技能由 Supervisor 亲自执行。参考规则通过 `read_skill_reference` 按阶段完整加载，工具仅负责读取与保存。
参考文件中的结构化输出格式用于组织工作记录；正文修改通过 `update_node` 完成，用户回复使用 `respond_to_user`。

## 完成标准

记忆具有正文依据，章节笔记中的事实与最终版本一致，作者要求与有效创作设计完整保留，下一章能读到章末状态与未决线索；作者能从简明条目中读懂关键事实、当前状态和待续计划。

## 执行流程

1. 用 `read_node_content` 读取已保存的最终章节，保留返回的 `content_sha256`，读取已有完整 notes、相关角色和已有记忆。
2. 用 `read_skill_reference` 完整读取 `summary.txt` 和 `story_memory.txt`，自行编写完整章节笔记，按用途组织章节事实摘要、作者要求、创作设计、连续性数据，有内容的类别才展开。合并已有有效要求与设计，以当前有效决定表达本轮纠错；计划与已发生事实分别标识。连续性数据简明记录后续会用到的能力、章末位置/物品/伤势/人物认知、关系变化和未决线索；日常、风物与支线互动中有后续作用的风物锚点、人情往来及潜在支线钩子同样保留。影响行动、设定或后续核对的数量完整记录来源/获得/消耗/结余，保留来源章节与真实角色 UUID。
   事实摘要概括当前正文的关键事件和结果，创作设计保留可继续执行的紧凑事件骨架，作者要求完整保留条件、例外和指定措辞。每项事实集中表达，同义条目合并；版本调整记录和核对过程保留在当前任务记录中。例如当前正文首次约定明后天行动，事实摘要记录该约定，作者要求记录该时间安排的有效条件。人物认知标明信息获得途径。后续写作从这些不同用途的条目中整理完整当前任务；完整正文与作者输入保持原文加载，生成笔记时按有效信息组织长度。
3. 用 `save_chapter_notes(chapter_node_id, notes=完整章节笔记, expected_content_sha256=回读值)` 保存完整章节笔记。
4. 如保存提示正文版本已变化，回读最新正文后重新核对笔记，再保存。
5. 用角色节点同步确有正文依据的变化。用 `read_node_content` 回读章节笔记。
