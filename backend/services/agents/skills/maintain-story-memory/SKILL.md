# 维护故事记忆

本技能由 Supervisor 亲自执行。参考规则通过 `read_skill_reference` 按阶段完整加载，工具仅负责读取与保存。
参考文件中的结构化输出格式用于组织工作记录；正文修改交由 `run_writing_agent`，用户回复使用 `respond_to_user`。

## 完成标准

记忆具有正文依据，章节笔记中的事实与最终版本一致，作者要求与创作设计完整保留，下一章能读到章末状态与未决线索。

## 执行流程

1. 用 `read_node_content` 读取已保存的最终章节，保留返回的 `content_sha256`，读取已有完整 notes、相关角色和已有记忆。
2. 用 `read_skill_reference` 完整读取 `summary.txt` 和 `story_memory.txt`，自行编写完整章节笔记，分为章节事实摘要、作者要求、创作设计、连续性数据。合并已有有效要求与设计，记录本轮纠错；计划与已发生事实分别标识。连续性数据逐项列出数量来源/获得/消耗/结余、能力、章末位置/物品/伤势/人物认知、关系变化和未决线索，引用来源章节与真实角色 UUID。
   事实摘要描述当前正文中发生的事，版本调整记录归入作者要求与创作设计。例如当前正文首次约定明后天行动，事实摘要记录该约定；“从今晚改到明后天”归入编辑记录。人物认知逐项标明信息获得途径。后续 Writer 交接从这些不同用途的条目中整理当前有效任务。
3. 用 `save_chapter_notes(chapter_node_id, notes=完整章节笔记, expected_content_sha256=回读值)` 保存完整章节笔记。
4. 如保存提示正文版本已变化，回读最新正文后重新核对笔记，再保存。
5. 用角色节点及关系工具同步确有正文依据的变化。用 `read_node_content` 回读章节笔记，并核对相关角色关系。
